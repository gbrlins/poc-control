# SUSE Toolkit (poc-control): situação, planos e decisões (18/11/2026)

## O que é
Ferramenta para cobrir o ciclo de uma PoC de ponta a ponta: **planejar** o escopo, **executar** com semáforo por item
(verde/amarelo/vermelho) e acompanhamento de sessões, e fazer a **triagem automática de TR/edital (RFI)** contra o portfólio SUSE.
Usa o Gemini (extração, classificação, tradução) e uma base de **procedimentos validados** que cresce a cada PoC.

O código vive só no GitLab: https://gitlab.suse.de/sa/poc-control (os repositórios antigos do GitHub e as imagens do Docker Hub
foram aposentados).

## O que estamos planejando (ainda não começou)
### 1. Revisão completa de UI/UX
- Prioridade: o **fluxo diário do SA** (planejar → executar → reportar; triagem de RFI).
- Método: revisão minha dos fluxos em PT/EN/ES, tema claro/escuro e só teclado, **mais 2–3 sessões curtas com SAs** fazendo tarefas reais.
- Meta de acessibilidade: WCAG 2.1 AA nas telas do app; melhor esforço no planejador.
- Entrega: lista de achados priorizada e, depois, correções em merge requests pequenos (componentes compartilhados primeiro).
- **Peço a ajuda de vocês:** quem puder participar de uma sessão de ~30 min ou mandar o que mais atrapalha no dia a dia, fale comigo.

### 2. Renomear todo o código para inglês
Motivo: o projeto será mantido também por programadores que não falam português. Em etapas, cada uma num merge request:
arquivos e pastas → identificadores → comentários e documentação → caminhos e campos JSON da API → banco de dados (por último,
ensaiado numa cópia dos dados reais) → chaves de tradução → prompts do Gemini (com comparação antes/depois) → regras para não regredir.
O que **continua em português** de propósito: os textos da interface em pt-BR, os procedimentos de exemplo e os nomes do portal PNCP.
Estimativa: cerca de duas semanas de trabalho, começando **depois** da demonstração.

## Decisões tomadas
- GitLab é a única casa do código; as regras da casa antiga (GitHub, Docker Hub, aviso no Slack) não valem mais.
- Inglês como idioma padrão (público global), com pt-BR e espanhol completos.
- Idioma guardado por campo + tradução sob demanda com cache; o banco nunca recebe a tradução.
- Não vamos construir o "rascunho guiado por IA" para RFI (a v2 o citava, mas nunca existiu); ideia futura registrada: **transformar
  itens de RFI em itens de PoC** (continuidade RFI → PoC).
- Renomeação para inglês: escopo completo e em etapas; prompts traduzidos com verificação; só a Raspberry e máquinas locais usam o
  sistema hoje, então a API antiga não precisa de compatibilidade longa (arquivos JSON exportados antigos continuam importáveis).
- UI/UX: foco no fluxo diário; revisão do especialista + sessões com SAs; correções em MRs pequenos.
- Ordem: demo → atualizar a Raspberry → renomeação (etapas 0–2) → correções de UI/UX.

## Limitações conhecidas
- Ainda **não testamos com uma chave Gemini real** a qualidade da tradução e da extração (só com simulações).
- Reiniciar a API interrompe análises em andamento (rodam dentro do processo); basta usar "Tentar de novo".
- Resumo executivo e pontos de sessão aparecem no texto gravado (só os relatórios traduzem).
- Em tela de celular, a Home e a página da PoC rolam para o lado; o foco de uso é notebook.

Planos detalhados (em inglês): `docs/plans/ux-review.md` e `docs/plans/english-rename.md`.
